# Hyperliquid 只读同步实施计划

> **执行说明：**按步骤实施并在任务记录中跟踪。用户要求使用 edit 工具修改代码，且未经明确要求不运行测试、构建或提交；这些约束优先于通用技能流程。

**目标：**把一个 Hyperliquid 主网永续账户的当前和后续仓位同步为可复盘的交易记录，平仓后自动完成，手工复盘内容不被覆盖。

**架构：**Express 服务端读取官方公开 `info` 接口，在 SQLite 中保存账户配置、成交去重键、游标和同步状态。成交按账户、品种和持仓方向归并成交易生命周期；React 在登录后触发同步和定时刷新，设置页管理绑定，记录页显示来源与状态。

**技术栈：**现有 React 19、Express 5、SQLite / better-sqlite3；使用 Node 内置 `fetch`，不增加签名或下单依赖。

**设计依据：**[Hyperliquid 只读同步设计](./2026-09-30-Hyperliquid-只读同步.md)

## 全局约束

- 仅支持主网默认永续市场与一个实际账户地址；只读，不收集私钥。
- 自动字段与手工复盘字段分离，历史手工交易和演示数据不改写。
- 同步失败、成交缺口和仓位不一致须可见；不得用仓位消失推断已平仓。
- 注释、日志和文档使用简体中文；不自动运行测试或构建，不自动提交。

## 重点审查

- 同一成交重复返回或两次同步重叠：只入库一次，不重复累计盈亏。
- 同一笔部分平仓后再加仓：保持同一记录，并分别累计已实现盈亏与费用。
- 一笔成交反手：旧方向结束，新方向开始，数量不丢失。
- 接入前已有仓位：标识为接入前持仓，未知入场时间和历史费用不伪造。
- 接口失败、分页窗口截断或快照与成交推导仓位不符：保留上次可信记录并提示人工核对。

## 文件边界

- `server/db.js`：增加绑定、成交去重和同步状态表，以及交易来源列和索引。
- `server/hyperliquid/client.js`：校验地址、调用带超时的官方只读接口、解析仓位与成交。
- `server/hyperliquid/reconcile.js`：纯函数归并成交，产出开仓、加仓、部分平仓、完全平仓及反手动作。
- `server/hyperliquid/sync.js`：抓取增量数据，在事务中去重、更新游标与自动交易，保留手工字段。
- `server/routes/hyperliquid.js`：当前用户的绑定、解绑、状态和手动同步接口；`server/index.js` 注册路由。
- `client/src/hooks/useApi.js`：封装上述接口。
- `client/src/components/HyperliquidSettings.jsx`：设置页的地址、连接与同步状态。
- `client/src/App.jsx`、`client/src/components/JournalCard.jsx` 和必要的复盘/表单组件：触发刷新并区分自动来源、开放中的持仓与手工复盘字段。
- `README.md`、`CLAUDE.md` 和设计任务记录：同步口径、限制与实际验证状态。

- [ ] 在 `server/hyperliquid/reconcile.js` 实现 `reconcileFill(position, fill)`，以 `startPosition`、成交方向和数量计算成交前后持仓；输出可复现动作，保留 `closedPnl` 与费用原值。
- [ ] 在 `server/hyperliquid/sync.js` 实现首次当前仓位导入和按游标增量抓取；按成交时间及唯一 ID 稳定排序，数据库事务内先去重再更新关联交易、游标和状态。

- [ ] 快照与推导持仓不符、达到历史窗口限制或请求失败时记录可见错误；不猜测平仓，也不推进遗漏成交的游标。
