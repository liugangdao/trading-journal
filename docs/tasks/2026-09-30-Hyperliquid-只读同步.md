# Hyperliquid 永续合约只读同步

## 目标与验收

- 当前登录账号绑定一个 Hyperliquid 主网永续合约账户地址。只读取公开账户数据，不要求私钥，也不发送交易指令。
- 绑定后现有持仓出现在交易记录中，状态为“进行中”；后续开仓自动新增进行中记录，完全平仓后同一条记录变为“已结束”。刷新页面或断线重连不产生重复记录。
- 加仓保留同一笔记录；部分平仓仍显示进行中，累计已实现美元盈亏；反手将原方向结束并建立反方向新记录。以成交事实为准，不把挂单当成持仓。
- 自动字段包括来源、品种、方向、时间、持仓数量、入场均价、出场信息和交易所已实现盈亏。入场理由、失效条件、退出原因、执行标签、好交易判断、截图及 R 由用户复盘填写，同步不覆盖。
- 同步失败或数据不完整时显示状态和错误，不把消失的仓位臆断成已平仓；手工交易及此前演示数据不受影响。

## 范围与方案

- 第一阶段仅支持主网默认永续合约市场、一个账户地址。用户提供的地址通过设置页绑定到当前登录账号，不硬编码到前端或代码。子账户需要绑定实际子账户地址；现货及其他 perp DEX 暂不纳入。
- 服务端使用官方 `info` 接口读取 `clearinghouseState` 与 `userFillsByTime`。首次连接读取当前仓位，并从绑定时刻开始记录后续成交；不自动导入绑定前已结束的历史交易。客户端打开时触发同步，并定期刷新；重新打开后按持久化游标补齐遗漏成交。
- 每条成交保存交易所唯一标识和原始必要字段；账户与品种分别维护同步游标/当前交易关联。先持久化成交，再在数据库事务内归并交易，避免重复和半写入。历史查询到达官方窗口限制时停止并提示需要人工核对，不静默跳过。
- 一笔交易按同品种同方向、从持仓由零变为非零到回到零的生命周期归并。部分平仓累计 `closedPnl`，反手按成交的 `startPosition` 与 `sz` 拆分；费用单独记录，界面明确显示美元盈亏的费用口径。尚未确认的历史持仓时间或盈亏留空并标明“接入前持仓”。
- 自动同步记录与手工记录使用不同来源标识。自动字段只在对应的同步记录上更新；用户填写的复盘字段始终保留。删除绑定时把当前同步持仓标记为已脱离，历史交易仍保留；再次绑定同一地址时使用新的当前仓位快照。
